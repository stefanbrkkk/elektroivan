## Phase 2 — motion-engineer
- **ScrollTrigger only sorts its triggers when at least one of them declares `refreshPriority`** (gsap 3.15 `ScrollTrigger.js`: `_sort = 1` is set inside `if ("refreshPriority" in vars)`, and `_refreshAll` runs `_sort && ScrollTrigger.sort()`). Without it, triggers refresh in creation order, so every trigger created before the Anatomy/Process pins measured a document that had not been re-spaced yet — the Contact scene sat ~5000px off, never fired, and `ScrollTrigger.refresh()` could not fix it because the order never changed. `MainLine`'s document-progress trigger now declares `refreshPriority: -999`: that both switches the whole page to position-ordered refreshing (`_sortY`) and makes the `end: 'bottom bottom'` document-height trigger refresh last, after all pins have re-applied their spacers. Any new ScrollTrigger elsewhere can keep the default priority 0 and will be measured correctly.
- The finale scene plays from `onToggle`/`onRefresh` instead of `onEnter`/`onEnterBack`: enter callbacks are suppressed while ScrollTrigger is refreshing, so a refresh (fonts, pin spacers, resize) landing while the section is already on screen would leave the card hidden forever. Its 2.5s safety net also writes `data-on`/`data-lit` by hand, because `timeline.progress(1)` is a seek and seeks suppress callbacks.
- No-JS / slow-boot safety net for content that starts hidden: `.jv-veil` (opacity 0) and `.jv-unlit` (opacity 0.16, keeps the hero H1 paintable for LCP) in `src/motion/motion.css` reveal themselves with a delayed CSS animation, and `unveil()` strips the class in the same layout-effect tick GSAP takes over. `isLateBoot()` (>1.7s since navigation) makes entry animations jump to their end state instead of replaying over content the CSS fallback already revealed. Same pattern for the intro overlay (`.jv-intro-auto`), which therefore ships visible in the prerendered HTML — no flash of an already-loaded page before the loader appears.
- Chromium logs `"<path> length cannot be measured when vector-effect is non-scaling-stroke and the element isn't proportionally scaled"` (a console *warning*, i.e. a G2 failure) when DrawSVG measures a path inside a `preserveAspectRatio="none"` SVG. `CurrentPath` therefore applies `vector-effect` only to the decorative sheath/copper strokes, never to the two paths DrawSVG measures.
- Anatomy is one scrubbed master timeline of 16 segments (5 steps × fault/fix/flow + a closing beat). All step state (`data-step`, `data-beat`, counter text, dot state, `data-lit`, the live arc/bulb flicker loops and spark emitters) is derived from `timeline.progress()` in its `onUpdate` and written straight to the DOM — no React state, so scrubbing never re-renders, and the state is correct after jumps in both directions (GSAP suppresses `.call()` callbacks on seeks, which is why callbacks are not used for it).
- The five step cards are all rendered and stacked (`.jv-card-stack`), cross-faded by the timeline, rather than swapped through React — this is what makes the reduced-motion variant (all five cards in flow, no pin) the same markup with no animation.
- Phones do not get a single vertical column of five components: at 360×640 the drawing may occupy ~30svh, which would shrink each component to a few pixels. `getCircuitLayout(vertical)` returns a **serpentine** (three rows, current still flowing downward) whose aspect ratio matches the available box, so components stay ~3× larger. Node positions along the path are measured from the rendered path at runtime (240 samples, nearest point), so neither layout carries hand-kept progress numbers.
- Main line geometry is rebuilt inside `refreshInit` (pin spacers already in the DOM) after collapsing the overlay to `height: 0` first, so a shrinking document is never propped open by a stale overlay. Its bend amplitude is clamped to the real gutter (`gutter * 0.26`, 6–40px) instead of a fixed 24–40px: between 1024px and ~1200px the content column leaves less than 40px of gutter and fixed bends would run under the text.
- `Sparks` renders either a standalone `<svg>` or a bare `<g>` (`as="g"`) so the same component can sit in HTML (hero word, contact card) and inside the circuit SVG. Visibility is toggled through `data-active` + a CSS rule, so "sparks are visible during the fault beat" is observable from Playwright (a zero-opacity SVG group still reports a bounding box).
- `src/motion/types.ts` was extended (additively, nothing removed): `SparksProps.as/transform/spread/size/testId`, `CurrentPathProps.className/progress/pulseDuration/nonScalingStroke/testId`, `CurrentPathHandle.pulseOnce()` and a `FlickerFaultOptions` type for the repeating fault flicker.
- Photosensitivity: `flickerOn` is exactly three brightness changes inside ≤0.6s; `flickerFault` is one dip per ≥0.8s cycle (2 changes/cycle, well under 3/s); the breaker's short-circuit flash is a single up/down pair over 0.36s; sparks overlap continuously (spawn every 0.24s, 0.3–0.6s lifetimes) so they read as a steady shower rather than a strobe. All of it is skipped entirely under reduced motion.
- `e2e/motion.spec.ts` writes its evidence to `test-results/shots/`, which Playwright **clears at the start of every run** — run the motion spec last (or on its own) when collecting G3 evidence.

## Phase 3 — motion-engineer (perf)
- **`DrawSVGPlugin` re-measures its target on every tween `init`** (`getScreenCTM()` + `getBBox()`, then `style.strokeDasharray = 'none'` → `getTotalLength()` → restore): a write/read/write pair, i.e. two forced full-document layouts per target per init, and 415 ms of self time in a 9 s throttled trace — the single biggest boot cost. `CurrentPath` now uses the `stroke-dashoffset` scrub BRIEF §5.3 allows instead: one `getTotalLength()` per mount, `stroke-dasharray` written once, and every update writes only `stroke-dashoffset` (no reads, no layout). The glow copy shares the core's `d`, so one measurement covers both paths — which also stops the `display: none` glow (`.jv-glow-lg`, <1024px) from being measured at all. `DrawSVGPlugin` stays registered/exported per docs/CONTRACT.md.
- `CurrentPath.timeline()` tweens `stroke-dashoffset` as a real tween property rather than writing it from a timeline `onUpdate`: GSAP **suppresses callbacks on a seek**, and a scrubbed master timeline seeks its children, so a callback-driven draw would silently stop updating.
- **Heavy scenes initialise near the viewport** (BRIEF §7) through one shared `whenNear(element, build)` helper in `motion.ts` (IntersectionObserver, `rootMargin: '400px 0px'` — measured to be past the fold by 692/733/612 px at 412×823 / 360×640 / 1440×900, so it never fires during load).
- Anatomy reserves its height by keeping the **pin and its ScrollTrigger eager and building only the tweens lazily**. The paused master is created with one empty `to({}, { duration: segments })` spine, so its duration is 16 before and after the scene exists: the pin distance, the pin-spacer height and the `segment → progress` mapping never change, no extra `refresh()` is needed, CLS stays 0, and `data-step`/`data-beat`/the counter are already right while the visitor scrolls in.
- **One `ScrollTrigger.refresh()` per boot instead of four.** A refresh is ~130 forced full-document layouts (~260 ms at 4× CPU). `ScrollTrigger.config({ autoRefreshEvents: 'visibilitychange,resize' })` drops the `DOMContentLoaded` refresh (it fires before any trigger exists — the bundle is a deferred module) and the `load` one; `installMotionWatchers()` replaces both with a single settle refresh in the microtask after whichever of `load`/`fonts.ready` comes last (2.5 s cap), `requestRefresh()` is a no-op until that has run and afterwards debounces 240 ms while dropping requests that arrive with one pending, and the body `ResizeObserver` seeds its baseline from its own first callback so installing it forces no layout.
- **`ScrollTrigger.refresh()` re-applies the scroll offset it recorded, which cancels a scroll in flight** — a smooth `scrollIntoView()` from an anchor link dies ~12 px in, and `e2e/nav.spec.ts` fails deterministically at t768 (only visible once the boot refreshes were coalesced into one late refresh). A refresh therefore waits for 140 ms of scroll quiet, tracked by a passive capture-phase `scroll` listener that records a timestamp and never reads a scroll offset (4 s ceiling so it cannot be starved).
- Measured and rejected: `backdrop-filter` on the 33 `.glass` surfaces and `will-change: transform` on `.jv-field`/`.jv-track` are **not** main-thread costs (TBT proxy 1057 ms baseline vs 1264 ms / 1221 ms with them disabled — compositor work, not blocking). No builder-owned CSS was changed; please do not "optimise" `.glass` on suspicion.
- `Sparks` and `Contact` no longer restate their resting state with `gsap.set()` at mount (six emitters × up to 14 particles, and four opacity sets, all identical to the markup — one `getComputedStyle` each inside the boot task); the spark pool is reset only once a particle has actually been thrown.
- `MainLine` renders no `<svg>` below 1024px (it was `display: none` dead weight in the layout tree); the 2 px progress bar already carries the same scroll progress there.
- Result: Performance 82 → **91 median** (89–97 over five runs), TBT 534 → **55 ms**, Style & Layout 1254 → 664 ms, Script Evaluation 998 → 424 ms, long tasks 5 → 2, CLS 0. Full logs and the trace evidence: `docs/reports/phase3-motion-perf.md`.
## Phase 4 — builder (review-1.md fixes)

- **C1 root cause confirmed**: `document.documentElement.classList.add('cursor-none')` ran once on mount, independent of whether the custom cursor was actually shown — so a page loading with the pointer already inside the viewport hid the native cursor immediately and showed nothing until the visitor moved the mouse out of the window and back in (the only `show()` trigger was a bubble-phase `pointerenter` on `window`, which never fires for that case). - **M9 — a real cross-layer cascade bug, not just a missing class**: Tailwind v4's generated CSS declares layer order `theme, base, components, utilities` (confirmed in the built `dist/assets/*.css`); a **later layer always wins over an earlier layer for the same property, regardless of source order or selector specificity**. `.safe-top`/`.safe-bottom` live in `@layer components`, so simply adding the class alongside an existing Tailwind padding utility (`p-4`, in `@layer utilities`) — the literal fix review-1.md proposed — silently does nothing; verified this empirically with an isolated two-file cascade-layer reproduction before and after the fix (`padding-bottom` stayed the utility's `16px` until `!important` was added). Re-verified with the same harness using literal replacement values: header → exactly the inset, panel → base + inset.
- **Minor 8 heading order**: Trust's eyebrow `<p>` became an `<h2>` (same visual style, `site.trust.eyebrow`, no new copy). Section order is intro → nav → hero(h1) → **trust(h2)** → anatomy(h2) → services(h2) → …, so this stays a flat, sequential h1→h2 run — no skipped levels.
- **Minor 11 — the review's suggested opacity does not clear 3:1**: computed contrast for `color-mix(in srgb, var(--color-muted) 45%, transparent)` against `--color-bg` is **2.37:1** (color-mix with a `transparent` endpoint keeps the original hue and just scales alpha — `rgba(#9AA0B4, 0.45)` — then that gets alpha-composited onto `#0A0B10`), still short of WCAG 1.4.11's 3:1. Applied to `border-line-strong` (a real Tailwind utility, since `--color-line-strong` is a `@theme` token) on Trust's/Testimonials' marquee toggles and Footer's back-to-top. **Not applied** to Hero's "Pogledaj usluge" or Contact's "Kopiraj" — both live in motion-engineer-owned files, out of scope here.

## Phase 4 — motion-engineer (review-1.md fixes)

Fixed M5, M6, the motion-engineer halves of M3, M9 and minor 11, plus minors 1, 2, 3, 4, 12, 15, 16 and 17 from `docs/reports/review-1.md`. Full log in `docs/reports/phase4-motion.md`.

- **Correction to the phase 2 and phase 3 notes above: `timeline.progress(1)` does *not* suppress callbacks.** `gsap-core.js`'s `progress(value, suppressEvents)` (line ~1715) forwards `suppressEvents` verbatim, so an omitted argument is `undefined` → falsy → `onComplete`/`onUpdate` **fire**; it is `seek()` (line ~1868) that wraps it in `_isNotFalse` and therefore defaults to suppressed. `ScrollTrigger.js:1715` scrubs with `animation.totalProgress(clipped, !!(_refreshing && (lastRefresh || reset)))` — suppressed *only* while ScrollTrigger is refreshing, not during ordinary scrubbing. Two consequences: (a) `IntroReveal`'s interrupt (`timeline.progress(1)`) genuinely reaches `onComplete` → `markIntroDone()`, so interrupting the loader does fire the hero sequence (verified in the browser: wheel at t=150ms → intro hidden, all three hero words at opacity 1, plug cable drawn); (b) the reason not to drive Anatomy's step state from `.call()` is *refresh* suppression plus jump/reverse ordering, not seeks in general — deriving it from `master.progress()` in `onUpdate` remains correct, just for a narrower reason than recorded. `Contact`'s manual `setOn(true)` next to its safety-net `progress(1)` is harmless belt-and-braces and stays.
- **BRIEF §6.11 beat 1 is now a real beat, on every viewport.** `Contact` owns the last 120px of cable into the switch — a short `CurrentPath` stub carrying `[data-mainline-end]` — energized at `t=0` of the finale timeline, with everything else shifted behind it. `MainLine` ends on the stub's left edge on ≥1024px; below 1024px there is no site cable at all, so the stub *is* the arrival (a `<1024px` `mask-image` fade lets it emerge from the dark rather than start in mid-air). This is why the stub exists rather than simply lengthening `MainLine`: the phone had no beat 1 whatsoever.
- **The main line's energized part no longer completes at the document bottom.** `end: 'bottom bottom'` meant the tip only reached the switch once the page was scrolled past the footer, with the switch off screen, so the finale always played over a cable ~200px short of it. The trigger now ends at `+=arrivalScroll()`, the scroll offset at which `[data-mainline-end]` sits at 75% of the viewport; it is a function, so `invalidateOnRefresh` + `refreshPriority: -999` recompute it after the pins have re-spaced. The finale's own enter trigger moved from the section (`top 60%`, a whole viewport early — the section top is ~285px above the switch) onto the **switch** at `top 60%`. Both being timed off the same element makes "current arrives, *then* the switch flips" true by construction, ~110px of scroll apart at 1440×900 and ~75px at 360×640, instead of true by luck.
- **`filter` is applied before `clip-path`, so you cannot blur a clipped element's own edges.** The light cone's two hard diagonals survived every blur put on `.jv-cone` itself. Moving the wedge to `.jv-cone::before` and leaving the blur on the parent softens them, because the parent's filter rasterises the already-clipped child. The cone is also a sibling of the *card* now, anchored `top-24 -bottom-16` rather than a fixed `h-[420px]`, so at every viewport it ends 64px below the card and the gradient's `transparent 96%` lands past the glass instead of as a seam across it.
- **Reduced motion creates no ScrollTrigger in `MainLine` at all** (BRIEF §5.2 removes scrub): `build()` writes `stroke-dashoffset: 0` and the mobile bar `scaleX(1)` once, and only `refreshInit` stays subscribed — a re-measure, not a scrub. Full length is the end state, consistent with every other reduced-motion surface (all five anatomy steps done, bulb lit, card usable).
- **`SparksProps.faultGlyph`** (additive, default `false`): the reduced-motion static arc glyph is now opt-in and used only on the hero's "Varniči?". Rendered unconditionally it put a stray blue squiggle under the "Kopiraj" button and on the *repaired* circuit beside "Spojeno. Bez varnica." — it read as a rendering bug, not an illustration.
- **One property, one owner.** The live fault loops (`flickerFault`) were tweening `opacity`/`autoAlpha` on the very elements the scrubbed master also tweens, so scrubbing through a fault beat could park them at whatever the killed loop had last written. Each now animates a dedicated element the master never touches: the arc is a `<g>` (master: `autoAlpha`) around a `<polyline data-part="arc-flicker">` (loop: `opacity`), and the bulb gained a sibling `<circle data-part="bulb-flicker">`. `stopLoops()` parks both with a direct `style.opacity` write rather than `gsap.set` — a single owner has nothing to read back, so a segment change costs no style resolution.
- **`.jv-stage-svg` is `width: 100%; height: auto`, so the viewBox's aspect ratio is what sizes the drawing** — raising the viewBox height is what fills the stage, and it scales every component up at the same time. The desktop circuit went from `M 140 220 H 900 V 112` in a `14 44 950 268` box (3.5:1, ~135px of the stage's 487) to `0 0 720 480` (1.5:1, ~400px of 487, components a third larger): supply side across the top, the damaged cable dropping down the vertical run, socket and switch along the bottom, bulb hanging above the switch.
- **GSAP resolves a percentage `transformOrigin` against `getBBox()`, which is not a component's own (0, 0).** The cable group's bbox is `[-109, -123, 204, 210]` once its halo and spark pool are counted, so letting the timeline write `rotation: 90` on it rotated the component about that centre and slid it ~140 user units off the path (`matrix(0,1.08,-1.08,0,302,274)` where `(440, 240)` was wanted). `CircuitNode.rotate` is therefore applied as a **static inner `<g transform="rotate(…)">`** in `CircuitSvg`; the node group the timeline drives only ever carries x/y/scale. Anything else that needs to follow the line direction must do the same.
- **Detail has to be drawn in strokes, not in `--color-bg` fills.** At the DIM 0.5 opacity unlit components sit at, a background-coloured hole on a dark stage is invisible, which is why the socket and switch read as blank boxes in every `anatomy-*` shot. Both now carry stroked geometry (Schuko recess + pin holes + earth clips + fixing screw; switch plate screws, rocker lit edge and pivot line).
- **`e2e/motion.spec.ts:320` was failing at `ad156c8`, before this phase** (confirmed by stashing every source change and re-running: still failed, 3/3). The first screenshot after a programmatic `scrollTo(0, 0)` comes off a compositor layer Chromium is still settling and rasterises six anti-aliased pixels on the scroll-hint dot differently (deltas 5–11/255, always the same six); nothing moves — the element's box matches to five decimals, its attributes are byte-identical, and frames 1/2/3 are byte-identical to each other. Only frame 0 differs. Fixed with one thrown-away warm-up capture before the compared pair; the assertion stays an exact `Buffer.compare(…) === 0`.
