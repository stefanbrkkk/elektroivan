## Phase 1 — builder
- `gsap/all` has no type declarations for gsap 3.15 (implicit `any`, `TS7016`); `src/motion/motion.ts` imports `gsap`, `gsap/ScrollTrigger`, `gsap/SplitText`, `gsap/DrawSVGPlugin`, `gsap/MotionPathPlugin` from their individual subpaths instead — typechecks cleanly under `strict`.
- `gsap.*` ambient types (`gsap.TweenTarget`, `gsap.core.Timeline`, …) come from gsap's global namespace declaration merged in from `gsap-core.d.ts`; `src/motion/types.ts` uses them with no import (an `import type { gsap } from './motion'` shadows the global and is reported unused by `noUnusedLocals`).
- `@eslint/js` added as an explicit devDependency (10.0.1) — required directly by the flat `eslint.config.js` but not shipped as a transitive dependency of `eslint` itself.
- `@types/node`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `globals` were not pinned in the table above; resolved to each package's latest version compatible with eslint 10 / React 19 (22.20.3, 7.1.1, 0.5.7, 17.12.0 respectively).
- Trust's and Testimonials' marquee pause/play toggle buttons both reuse `site.testimonials.pause`/`.play` ("Pauziraj/Pokreni traku") — the `SiteConfig` schema (frozen by CONTRACT) has no separate label for Trust's marquee, and the wording is generic enough ("traku" = the strip) to fit both.
- The one-time `img, svg { display: block }` reset originally added to `global.css` was removed entirely rather than kept behind `@layer base`: on this Tailwind v4.3.3 + `@tailwindcss/vite` pipeline a custom rule duplicating a selector Tailwind's own preflight already owns is not reliably reordered relative to generated utilities (verified empirically — it silently defeated `hidden`/`lg:block`/`lg:hidden` on `<svg>`), even wrapped in `@layer`. Tailwind's preflight already sets `display:block` on `img`/`svg`/etc. correctly, so the duplicate was both redundant and buggy. The rest of the resets/utility-like classes stay grouped in `@layer base`/`@layer components` (confirmed safe: `.glass`'s `border-radius` correctly loses to a `rounded-full` utility on the same element).
- `.focus-ring` is scoped to `:focus-visible` (`.focus-ring:focus-visible { outline: … }`), not a permanently-applied outline — the earlier unscoped version showed a permanent ring around every link/button.
- Anatomy's five step-navigation dots keep a small 10×10px visual dot but size the actual `<button>` hit area to 44×44px (`h-11 w-11`, inner `<span>` for the dot), per BRIEF §7's ≥44px touch-target rule (also flagged by Lighthouse's `target-size` audit).
- `og-build.mts` and `og.html` render via `page.goto('file://<temp-file>')` rather than `page.setContent()` — Chromium blocks `file://` subresources (fonts, the favicon image) from a document that isn't itself `file://`-origin, which would otherwise silently fall back to system fonts / a broken icon.
- Lighthouse 13.4.1 ships a 5th "Agentic Browsing" category by default; `scripts/lighthouse.mts` explicitly filters to the four BRIEF §7 categories (performance, accessibility, best-practices, seo) rather than printing whatever the installed version happens to report.
- The display-font woff2 preloaded in `index.html` is committed as a static file at `public/fonts/bricolage-grotesque-latin-wght-normal.woff2` (copied once from the installed Fontsource package) — simplest way to get a stable `/fonts/...` URL for the `<link rel="preload">` without a custom Vite plugin.

## Phase 2 — builder
- **Real Chromium bug found and worked around**: applying a 3D `transform: perspective(...) rotateX()/rotateY()` (for Services' cursor-tilt, BRIEF §6.6) to a `flex h-full flex-col justify-between` box that is itself a narrow CSS Grid item makes the pinned Chromium build (`/opt/pw-browsers/chromium`, revision 1194) report a corrupted `getBoundingClientRect()`/computed height (0px or exactly half) for descendant `<svg>` icons — verified independent of GSAP (reproduced with `prefers-reduced-motion: reduce`, which skips all GSAP code, and with an isolated non-React repro page). Fix: the `<article class="service-card">` keeps the original `flex flex-col justify-between` layout (and owns no transform of its own), and the pointer-tilt transform is scoped to a small `inline-block` wrapper around only the 28×28 icon — never around a flex/percentage-height box. Verified the six icons render at their correct size in every bento cell (`sm`, `md`, `lg`) after the fix, tilt/spotlight still animate on hover.
- Nav's mobile-panel breakpoint changed from the phase-1 baseline's `768px` to **1024px**, matching BRIEF §6.2's "Mobile (<1024px)" wording literally (`useMediaQuery('(min-width: 1024px)')`, `lg:` Tailwind prefixes) — phase-1's placeholder used `md:` (768px). This also makes `t768` a mobile-menu viewport per the phase-2 delegation's e2e list.
- Trust's and Testimonials' marquee pause state was previously a single boolean shared between hover and the explicit toggle button; hovering off would silently un-pause a row the visitor had explicitly paused (and, worse, Testimonials wrapped the *entire* `<section>`, including the toggle button itself, in the hover/focus handlers — focusing the toggle after a click kept the row paused forever regardless of the toggle's own state, caught by `interactions.spec.ts`). Fixed by tracking `hovered` and `manualPause` separately (`paused = hovered || manualPause`) and scoping Testimonials' hover/focus handlers to the row-track container only, not the toggle button.
- BeforeAfter's `ba-slider` arrow-key step changed from the phase-1 placeholder's `±5` to **`±2`** per the phase-2 delegation, and its hit area widened from `w-0` (a literal zero-width slider, centered exactly on the 1px divider line) to `w-11` (44px, meeting the §7 touch-target rule) — the whole track already handled drag-from-anywhere, but the focusable `role="slider"` element itself had no real target size.
- FAQ's height-open/close transition uses a `grid-template-rows: 0fr → 1fr` trick on the panel itself (not a hard `hidden` toggle) so it can animate; the global `@media (prefers-reduced-motion: reduce)` rule (phase 1, `transition-duration: 0.001ms !important`) already makes this instant with no extra JS branch. `aria-hidden` on the panel is kept in sync with `aria-expanded` for screen readers independent of the animation.
- `Cursor.tsx` is rendered as a sibling of `<App/>` (`<><App/><Cursor/></>`) in both `main.tsx` and `entry-server.tsx`, never inside `<App/>`, which is frozen/motion-engineer-owned — this keeps the hydrated tree shape identical to the server-rendered one (Cursor renders `null` on the server and on the first client render, matching the project's existing SSR-safe hook pattern) without touching `App.tsx`.
- `playwright.config.ts` now reads `PW_PORT` (webServer port, default 4173 unchanged) and `PLAYWRIGHT_BASE_URL` (skip launching a webServer entirely) so this agent's own `test:e2e` runs never collide with another agent's preview server on the same machine.

## Phase 2 — motion-engineer
- **ScrollTrigger only sorts its triggers when at least one of them declares `refreshPriority`** (gsap 3.15 `ScrollTrigger.js`: `_sort = 1` is set inside `if ("refreshPriority" in vars)`, and `_refreshAll` runs `_sort && ScrollTrigger.sort()`). Without it, triggers refresh in creation order, so every trigger created before the Anatomy/Process pins measured a document that had not been re-spaced yet — the Contact scene sat ~5000px off, never fired, and `ScrollTrigger.refresh()` could not fix it because the order never changed. `MainLine`'s document-progress trigger now declares `refreshPriority: -999`: that both switches the whole page to position-ordered refreshing (`_sortY`) and makes the `end: 'bottom bottom'` document-height trigger refresh last, after all pins have re-applied their spacers. Any new ScrollTrigger elsewhere can keep the default priority 0 and will be measured correctly.
- The finale scene plays from `onToggle`/`onRefresh` instead of `onEnter`/`onEnterBack`: enter callbacks are suppressed while ScrollTrigger is refreshing, so a refresh (fonts, pin spacers, resize) landing while the section is already on screen would leave the card hidden forever. Its 2.5s safety net also writes `data-on`/`data-lit` by hand, because `timeline.progress(1)` is a seek and seeks suppress callbacks.
- No-JS / slow-boot safety net for content that starts hidden: `.jv-veil` (opacity 0) and `.jv-unlit` (opacity 0.16, keeps the hero H1 paintable for LCP) in `src/motion/motion.css` reveal themselves with a delayed CSS animation, and `unveil()` strips the class in the same layout-effect tick GSAP takes over. `isLateBoot()` (>1.7s since navigation) makes entry animations jump to their end state instead of replaying over content the CSS fallback already revealed. Same pattern for the intro overlay (`.jv-intro-auto`), which therefore ships visible in the prerendered HTML — no flash of an already-loaded page before the loader appears.
- Chromium logs `"<path> length cannot be measured when vector-effect is non-scaling-stroke and the element isn't proportionally scaled"` (a console *warning*, i.e. a G2 failure) when DrawSVG measures a path inside a `preserveAspectRatio="none"` SVG. `CurrentPath` therefore applies `vector-effect` only to the decorative sheath/copper strokes, never to the two paths DrawSVG measures.
- Anatomy is one scrubbed master timeline of 16 segments (5 steps × fault/fix/flow + a closing beat). All step state (`data-step`, `data-beat`, counter text, dot state, `data-lit`, the live arc/bulb flicker loops and spark emitters) is derived from `timeline.progress()` in its `onUpdate` and written straight to the DOM — no React state, so scrubbing never re-renders, and the state is correct after jumps in both directions (GSAP suppresses `.call()` callbacks on seeks, which is why callbacks are not used for it).
- The five step cards are all rendered and stacked (`.jv-card-stack`), cross-faded by the timeline, rather than swapped through React — this is what makes the reduced-motion variant (all five cards in flow, no pin) the same markup with no animation.
- Phones do not get a single vertical column of five components: at 360×640 the drawing may occupy ~30svh, which would shrink each component to a few pixels. `getCircuitLayout(vertical)` returns a **serpentine** (three rows, current still flowing downward) whose aspect ratio matches the available box, so components stay ~3× larger. Node positions along the path are measured from the rendered path at runtime (240 samples, nearest point), so neither layout carries hand-kept progress numbers.
- Main line geometry is rebuilt inside `refreshInit` (pin spacers already in the DOM) after collapsing the overlay to `height: 0` first, so a shrinking document is never propped open by a stale overlay. Its bend amplitude is clamped to the real gutter (`gutter * 0.26`, 6–40px) instead of a fixed 24–40px: between 1024px and ~1200px the content column leaves less than 40px of gutter and fixed bends would run under the text.
- `Sparks` renders either a standalone `<svg>` or a bare `<g>` (`as="g"`) so the same component can sit in HTML (hero word, contact card) and inside the circuit SVG. Visibility is toggled through `data-active` + a CSS rule, so "sparks are visible during the fault beat" is observable from Playwright (a zero-opacity SVG group still reports a bounding box).
- `src/motion/types.ts` was extended (additively, nothing removed): `SparksProps.as/transform/spread/size/testId`, `CurrentPathProps.className/progress/pulseDuration/nonScalingStroke/testId`, `CurrentPathHandle.pulseOnce()` and a `FlickerFaultOptions` type for the repeating fault flicker.
- Photosensitivity: `flickerOn` is exactly three brightness changes inside ≤0.6s; `flickerFault` is one dip per ≥0.8s cycle (2 changes/cycle, well under 3/s); the breaker's short-circuit flash is a single up/down pair over 0.36s; sparks overlap continuously (spawn every 0.24s, 0.3–0.6s lifetimes) so they read as a steady shower rather than a strobe. All of it is skipped entirely under reduced motion.
- `e2e/motion.spec.ts` writes its evidence to `test-results/shots/`, which Playwright **clears at the start of every run** — run the motion spec last (or on its own) when collecting G3 evidence.

## Phase 4 — builder (review-1.md fixes)

Fixed C1, M1, M2, M3, M4, M8, M9 and minors 5–11, 13, 14 from `docs/reports/review-1.md` in the builder-owned files. Full log in `docs/reports/phase4-builder.md`.

- **C1 root cause confirmed**: `document.documentElement.classList.add('cursor-none')` ran once on mount, independent of whether the custom cursor was actually shown — so a page loading with the pointer already inside the viewport hid the native cursor immediately and showed nothing until the visitor moved the mouse out of the window and back in (the only `show()` trigger was a bubble-phase `pointerenter` on `window`, which never fires for that case). Fixed by moving `cursor-none` into `show()`/`hide()` themselves (native cursor hidden only while the custom one is visible, verified with a script that reads `getComputedStyle` before/after a synthetic `page.mouse.move()` — before: native visible, custom `opacity:0`; after: native hidden, custom `opacity:1`), calling `show()` as the first line of `handlePointerMove`, and swapping the `window` listener to `pointerover` (bubbles) as backup.
- **M1**: `ServiceCard` now gates pointer-tilt and the cursor-spotlight on `useFinePointer() && !usePrefersReducedMotion()` (a new `interactive` flag), and the whole hover CSS block in `global.css` gained `and (prefers-reduced-motion: no-preference)` alongside its existing `(hover: hover) and (pointer: fine)`. Verified with `reducedMotion: 'reduce'` + a synthetic hover: spotlight opacity stays `0` and no `pointermove` handler is attached.
- **M2**: removed `overflow-x: hidden` from `body`. `smoke.spec.ts`'s overflow assertion (`scrollWidth <= innerWidth`) passed on all four projects with no source-width fixes needed — no section actually relied on the body clip.
- **M4 verified by geometry**, not just by eye: with the gap moved onto every `<li>` (including the last), each marquee's first-half width is exactly 50.00000% of the full (duplicated) track width for both Trust's strip and both Testimonials rows (measured via `getBoundingClientRect()` sums), so `translateX(-50%)` lands on exactly one copy — no residual half-gap to snap on the loop.
- **M8**: `lg:auto-rows-[11rem]` → `lg:auto-rows-[minmax(11rem,auto)]`. Added the `services-1440.png` capture (d1440-only) to `e2e/interactions.spec.ts`, plus a geometry assertion that no card descendant's box extends past its own card; both the screenshot and the assertion are clean — the fixed-176px row was never actually overflowing at the current copy lengths, but the fixed row was still real latent risk the minmax fix removes.
- **M9 — a real cross-layer cascade bug, not just a missing class**: Tailwind v4's generated CSS declares layer order `theme, base, components, utilities` (confirmed in the built `dist/assets/*.css`); a **later layer always wins over an earlier layer for the same property, regardless of source order or selector specificity**. `.safe-top`/`.safe-bottom` live in `@layer components`, so simply adding the class alongside an existing Tailwind padding utility (`p-4`, in `@layer utilities`) — the literal fix review-1.md proposed — silently does nothing; verified this empirically with an isolated two-file cascade-layer reproduction before and after the fix (`padding-bottom` stayed the utility's `16px` until `!important` was added). Fixed by making `.safe-top`/`.safe-bottom`/`.safe-left`/`.safe-right` `!important` and additive via `calc(var(--safe-p*, 0px) + env(...))`, so a consumer that already has its own base padding on that edge (the mobile menu panel's `p-4`) sets `--safe-pb` inline and gets `base + inset`, while a consumer with no competing padding (the header's `safe-top`) just gets the inset. Re-verified with the same harness using literal replacement values: header → exactly the inset, panel → base + inset.
- **Minor 8 heading order**: Trust's eyebrow `<p>` became an `<h2>` (same visual style, `site.trust.eyebrow`, no new copy). Section order is intro → nav → hero(h1) → **trust(h2)** → anatomy(h2) → services(h2) → …, so this stays a flat, sequential h1→h2 run — no skipped levels.
- **Minor 11 — the review's suggested opacity does not clear 3:1**: computed contrast for `color-mix(in srgb, var(--color-muted) 45%, transparent)` against `--color-bg` is **2.37:1** (color-mix with a `transparent` endpoint keeps the original hue and just scales alpha — `rgba(#9AA0B4, 0.45)` — then that gets alpha-composited onto `#0A0B10`), still short of WCAG 1.4.11's 3:1. Used **60%** instead: `color-mix(in srgb, var(--color-muted) 60%, transparent)` → composited `rgb(96,100,114)` on `#0A0B10` → **3.36:1** (script: srgb→linear WCAG relative-luminance formula, cross-checked against the review's own stated `1.40:1` for bare `--color-line`, which the same script reproduces exactly). Applied to `border-line-strong` (a real Tailwind utility, since `--color-line-strong` is a `@theme` token) on Trust's/Testimonials' marquee toggles and Footer's back-to-top. **Not applied** to Hero's "Pogledaj usluge" or Contact's "Kopiraj" — both live in motion-engineer-owned files, out of scope here.
- **Minor 13**: the before/after "new panel" MCB row went from 6 to 5 breakers (`64 + i*44` for `i<5`, last ends at x=274) so the RCD module (now `x=310`, ends at 356) has a 36px gap on its left and a 4px margin before the enclosure's right edge at 360 — no more 2px overlap/overflow. The wiring fan-out and the RCD's centered "FID" label (`x=333`) were updated to match.
- **prerender.mts / minor 10**: `dist/sitemap.xml` and the `robots.txt` `Sitemap:` line are now both skipped while `site.siteUrl` is empty (verified in a real build: no `sitemap.xml` in `dist/`, no `Sitemap:` line, no `canonical` tag, `og:image` stays `/og.png`), with a one-line `console.log` note. README's build-steps section says so explicitly; the existing post-deploy paragraph already covered filling in `siteUrl` to regenerate these.
