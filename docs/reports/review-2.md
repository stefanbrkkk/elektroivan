## 2. Regression check of the phase-3 perf work

Everything below was re-derived from the code, not taken from the reports.

- **`whenNear` fallbacks.** `motion.ts:217-236` builds immediately when `IntersectionObserver` is absent, and the observer fires its first callback unconditionally after `observe()`. Both consumers keep their *reserved height* outside `build`: Anatomy's pin + its ScrollTrigger are eager (`Anatomy.tsx:183-194`, master duration fixed at `segments` by the empty spine at `:113-114`), Contact's section is plain flow. Both also catch up if the build lands late — `Anatomy.tsx:394` `if (trigger.progress > 0) master.progress(trigger.progress)` then `lastSegment = -1; applyState()`, and Contact's `enter` trigger plays on `onRefresh` as well as `onToggle` (`Contact.tsx:201-207`), which ScrollTrigger fires during the trigger's own creation refresh. Contact additionally has the 2.5s `delayedCall` safety net (`:220-229`) and the `.jv-veil` CSS fallback. See NEW-4 for the one gap.
- **Reduced motion.** Verified end-to-end and unchanged: `MainLine` creates no trigger (`:202-209`), `Anatomy` returns before `whenNear` with all five cards in a plain flex column and `lit` circuit (`:94-99`, `:510-526`), `Contact` sets the full end state and returns (`:108-118`), `Hero` (`:49-53`), `Process` (`:36-39`), `Sparks` (`:58-62`), `SmoothScroll` (`:31`), `Cursor` (`:20`), `IntroReveal` via `data-intro='skip'`. Confirmed visually in `finale-1440-reduced.png` / `finale-360-reduced.png` / `hero-*-reduced.png`.
- **Refresh coalescing vs. resize/pin re-measurement.** `autoRefreshEvents: 'visibilitychange,resize'` (`motion.ts:30`) leaves ScrollTrigger's own resize refresh in place, so a resize is never routed through the 240ms debounce — the debounce only covers the body `ResizeObserver` (2px dead band, baseline seeded from its own first callback, `:181-193`). `runRefresh` (`:96-103`) postpones only while the scroll is moving and is hard-capped at `REFRESH_DEADLINE` 4s, so it cannot be starved; `refreshPending` drops duplicates that one refresh would cover anyway. `refreshPriority: -999` on the document-height trigger both enables ScrollTrigger's position sort and makes it measure last.
- **The one real regression here was found and fixed at `1b0458b`** — see NEW-3. `refreshInit` is dispatched *before* `_revertAll()` **and before the triggers re-measure** (`node_modules/gsap/ScrollTrigger.js:495-511`), so a resize that changes pin distances left `MainLine`'s path built against stale spacers. `MainLine.tsx:293-313` now rebuilds again on `refresh` (dispatched at the very end of `_refreshAll`) and re-applies the scrub with `tween.invalidate().progress(st.progress)`; `motion.css:86` adds `overflow: hidden` to the layer so the collapse-to-measure trick actually shrinks `scrollHeight`. No feedback loop: the layer is absolutely positioned, so it never contributes to `document.body`'s `contentRect`.
- **Cleanup / StrictMode.** Every `useGSAP` returns a disposer and uses `revertOnUpdate: true`. New listeners are paired: `MainLine.tsx:292-293` ↔ `:296-297` and `:204-205` ↔ `:207-208`; `installMotionWatchers()` is ref-counted (`motion.ts:154,196-202`) and its disposer is called in the same cleanup. `whenNear` returns `observer.disconnect`. `CurrentPath` and `Sparks` reset `controls.current` to no-ops on teardown and are re-populated child-first on the next commit, which is why `Contact.tsx:110/124` and `Anatomy.tsx:97` can safely call into the handle from the parent effect. `Anatomy` nulls `triggerRef` on teardown. No double tickers (`SmoothScroll.tsx:35-41`).

## 3. New findings

Nothing critical or major. Seven minors, none blocking.

### MINOR

**NEW-1 — the mobile progress bar reaches 100% well before the page bottom.**
`src/motion/MainLine.tsx:265` (`end: () => '+=' + arrivalScroll()`) drives both the desktop cable *and* the `<1024px` progress bar (`:238` `setFill(progress)`). M5's fix ends that progress at the switch, so on a phone the amber bar is full while the contact card and the whole footer are still below — visible at the top of `finale-390-lit.png`. BRIEF §5.1 calls it a "traka napretka" and says the energized cable "raste sa ukupnim napretkom skrola".
*Fix:* give the bar its own trigger (`trigger: document.body, start: 'top top', end: 'bottom bottom'`) and keep `arrivalScroll()` for the cable only — two `onUpdate` consumers, one extra trigger.

**NEW-2 — `.safe-*` helpers use `env()` with no fallback, unlike `.jv-progress`.**
`src/styles/global.css:162-175` writes `calc(var(--safe-pt, 0px) + env(safe-area-inset-top))`, while `src/motion/motion.css:106,111-112` correctly writes `env(safe-area-inset-top, 0px)`. In a UA without `env()` support the whole declaration is invalid at computed-value time and, because it is `!important`, it *replaces* the utility it was meant to add to — the mobile menu panel (`Nav.tsx:200`, `p-4` + `--safe-pb: 1rem`) would lose its bottom padding entirely rather than fall back to 16px.
*Fix:* add the `, 0px` fallback to all four helpers, matching `motion.css`.

**NEW-3 — `services-1440.png` is stale evidence (the bug it shows is already fixed).**
Found independently before `1b0458b` landed: in the shipped `services-1440.png` the main line leaves the gutter at image y≈520 and sweeps across the bento, dead-ending inside the "Priključenje uređaja" card at (580, 700); the cable is also completely un-energized there (0 volt-coloured pixels along x=84-90, where ~50% of the path length should be amber at that scroll offset). Root cause — stale pin spacers on `refreshInit` after Playwright's element screenshot resizes the viewport — is exactly what `src/motion/MainLine.tsx:293-313` + `src/motion/motion.css:86` now fix.
*Fix:* none in code; **re-capture** `test-results/shots/` at `1b0458b` (the current set is from 03:53, the fix from 04:04) and confirm the cable stays in the gutter through the services section. Worth also capturing `services-1440.png` as a viewport-sized clip rather than a >viewport element screenshot, so the capture cannot perturb the pinned layout.

**NEW-4 — near-viewport init leaves two Anatomy elements with no fallback path.**
`src/sections/Anatomy.tsx:105-107` sets cards 2–5 and `[data-testid="anatomy-final"]` to `opacity: 0` **eagerly**, after `unveil()` (`:92`) has already stripped their `.jv-veil` CSS safety net, but the tweens that bring them back only exist inside `buildScene` (`:271-276`, `:391`). If `whenNear` never resolves (IO disabled by an extension, a pathological embedding), step cards 2–5 and "Spojeno. Bez varnica." are permanently invisible with no CSS fallback — unlike `Contact`, which has both a 2.5s safety net and `.jv-veil`. In practice IO always fires, so this is theory, not an observed failure.
*Fix:* move those two `gsap.set` calls into `buildScene`, or add the same `gsap.delayedCall` safety net Contact uses.

**NEW-5 — `Cursor.show()` runs for any pointer type.**
`src/components/Cursor.tsx:111` binds `show` directly to `pointerover`, while `handlePointerMove` guards on `event.pointerType !== 'mouse'` (`:46`). On a hybrid laptop (fine pointer *and* touch) a finger tap adds `cursor-none` and paints the dot/ring at the last mouse position. Harmless but contradicts BRIEF §4's "ništa od toga na touch uređajima".
*Fix:* `window.addEventListener('pointerover', (e) => { if (e.pointerType === 'mouse') show(); })`.

**NEW-6 — `og:locale` is not a valid Open Graph locale.**
`src/config/site.ts:61,161` and `scripts/prerender.mts:80` emit `og:locale="sr_Latn"`; shipped in `dist/index.html`. Open Graph expects `language_TERRITORY` (`sr_RS`); `Latn` is a script subtag and scrapers drop the tag. Same family as m10's unresolved half: `og:image` and the JSON-LD `image` remain relative `/og.png` while `siteUrl` is empty, which most scrapers will not resolve — correct to defer, but it means the OG payload is only complete after the §8 post-deploy `siteUrl` step. That step is documented (`README.md:49`), and canonical/sitemap are in the same boat; flagging so it is not forgotten at deploy.
*Fix:* `locale: 'sr_RS'`, and run the §8 re-build the moment the domain exists.

**NEW-7 — small residue in the anatomy composition.**
Three sub-pixel-budget items in `src/sections/anatomy/layout.ts:71-85` and `CircuitSvg.tsx`: (a) `lift: { x: 0, y: -20 }` is applied uniformly, so the cable node — the one on the *vertical* run (`rotate: 90`) — lifts *along* its own axis rather than perpendicular to the line; (b) the socket's halo (`CircuitSvg.tsx:270`, `ry=62` at y=430) reaches y=492 against a 480-tall viewBox and is clipped at the bottom during the fault beat; (c) the path's final riser `H 650 V 300` runs up the switch plate's right edge (plate spans 608–652) instead of leaving its top. Also carried over: m18 above.
*Fix:* a per-node `lift` (or derive it from `rotate`), viewBox height 500, and `V 300` from x=630.
